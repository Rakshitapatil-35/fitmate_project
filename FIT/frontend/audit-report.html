Part 1: Backend, Database & ML Pipeline Problems (11 Issues)

# File & Lines Severity Problem Occurring Root Cause & Fix Applied
1 backend/app/config.py (L19–65)
backend/.env (L9)		 Critical Empty SQLite DB & Missing Assets When Launched From Project Root DATABASE_URL="sqlite:///./size_recommendation.db", ML_MODEL_PATH, EASE_CONFIG_PATH, and env_file=".env" were relative to os.getcwd(). Starting uvicorn outside FIT/backend created an empty 0-row DB in the root directory. Fix: Anchored all paths to BACKEND_DIR = Path(__file__).resolve().parent.parent.
2 backend/app/routers/measurements.py (L50–257)
backend/app/dependencies.py (L77–101)		 Critical POST /api/v1/measurements Failed With 401 Unauthorized for Guest Users The frontend allows guest users (Continue as Guest) to save measurements on /measurements, which calls POST /api/v1/measurements without a JWT token. The router required get_current_user, throwing 401 Unauthorized. Also PUT /measurements/{id} dropped body_shape. Fix: Added get_current_or_guest_user dependency and persisted body_shape.
3 backend/app/services/model_service.py (L384–393)
backend/src/predict.py (L109–121)		 Critical Metric Waist Measurements (50–78 cm) Were Multiplied by 2.54 Into 127–200 cm predict_size() and predict_fit() passed waist_raw to parse_inches_to_cm() (multiplying by 2.54) and only reverted to cm if the result exceeded 200. For a 74 cm waist, 74 * 2.54 = 188.0 cm <= 200, so Models 1 & 2 treated a 74 cm waist as a 188 cm (74-inch) waist. Fix: Added parse_circumference_to_cm() so [16, 50) converts from inches while [50, 220] stays in cm.
4 backend/src/utils.py (L115–157) High parse_bust_size("90cm") Crashed With Out-of-Range ValueError (236.2 cm) The regex ^(\d{2})\s*([a-z]+)$ matched "90cm" as a 90-inch bra band with cup "cm" (+3 in), calculating 93 * 2.54 = 236.2 cm and throwing a validation error. Fix: Parsed explicit cm and in suffixes first and restricted cup matching to valid bra cup letters (aa–j).
5 backend/src/predict.py (L25–62)
backend/app/ml/predictor.py (L91–100)		 High FileNotFoundError in src/predict.py Caused 14 Test Failures & Tier-1 ML Fallback get_model_1(), get_model_2(), and get_model_3() used CWD-relative 'models/model_*.joblib'. Running outside FIT/backend caused Tier-1 ML inference and 14 tests in tests/test_fitmate.py to fail. Fix: Added _resolve_model_path() anchored to FIT/backend.
6 backend/app/services/recommendation_service.py (L23–39)
backend/app/services/ml_client.py (L150–200)		 High User Weight Omitted & Hardcoded size=8.0 / brand="FITMATE" Used in ML Enrichment extract_profile_measurements_cm() omitted weight_kg, causing Models 1, 2, 4, and 5 to always fall back to dummy weights (62–65 kg). In addition, ml_client.py hardcoded size=8.0 for Model 5 and brand="FITMATE" for Model 3. Fix: Passed user weight, actual brand name, and mapped recommended size label to numeric size.
7 backend/seed.py (L130–440)
backend/app/main.py (L30–45)		 High Missing Featured Retail Brands (Zara, H&M, Levi's, Uniqlo, Mango) in Database seed.py only seeded 2 brands (NordicThread, AuraAtelier), while the frontend defaulted to Zara. Moreover, main.py did not call seed_database() on startup. Fix: Added all 5 retail brands, products, and verified size charts to seed.py and auto-seeded during FastAPI startup.
8 backend/app/models/catalog.py (L119–135)
backend/app/schemas/catalog.py (L221–242)		 High ProductResponse Missing brand_name and category_code GET /api/v1/products returned brand_id and category_id without brand_name or category_code, breaking frontend brand filtering (p.brand_name === selectedBrandName). Fix: Added brand_name and category_code properties to Product and ProductResponse.
9 backend/app/routers/recommendations.py (L50–101) Medium GET /api/v1/recommendations Failed With 401 Unauthorized for Guests POST /api/v1/recommendations allowed guests, but GET /api/v1/recommendations required get_current_user, failing on /result and /history for guests. Fix: Used get_optional_current_user.
10 backend/app/routers/feedback.py (L26–39) Medium Guest Feedback Hardcoded user_id = 1, Risking Foreign Key IntegrityError submit_feedback hardcoded user_id = 1 when unauthenticated, failing if user ID 1 did not exist. Fix: Used get_current_or_guest_user.
11 backend/api/main.py (L82–150)
backend/tests/test_fitmate.py (L9–22)		 Medium Sync Endpoints in api/main.py + TestClient Hung in Windows Sandbox test_fitmate.py used Starlette's thread-portal TestClient against sync def endpoints in api/main.py, hanging on Windows socketpairs. Fix: Converted api/main.py routes to async def and used SyncASGITestClient.

Fix: Mapped body proportions to the corresponding visual archetype card while displaying the NHANES cluster match.
19 frontend/pages/BrandProductPickerPage.js (L16–65) High No "All Brands" Filter & Cross-Brand Search Returned 0 Products Searching for "Jeans" or "Chino" while Zara was active returned 0 items. Also hardcoded Stretch: 2% and failed if activeProfile.id was a local mock timestamp. Fix: Added "All Brands" filter, cross-brand search, dynamic stretch %, and inline measurement fallback.
20 frontend/routes/router.js (L103–106)
frontend/pages/BrandProductPickerPage.js (L213–231)		 High Page Jumped to Top on Every Click & Search Input Lost Focus After 300ms State updates fired hashchange, causing router.handleRoute() to scroll to top: 0, destroy focus on #brand-search-input, and re-fetch /brands and /products on every click. Fix: Preserved scroll position on same-route updates, restored search focus/caret, and cached catalog lists.
21 frontend/pages/ComparisonTablePage.js (L32–90) Medium Comparison Table Ignored Active Product Size Chart & Recommended Size renderComparisonTablePage() was synchronous and rendered a static mock table with Size M always marked as Recommended. Fix: Connected to live api.getComparisonMatrix(), api.getMultiBrandComparison(), and latestRecommendation.recommended_size.
22 frontend/pages/ResultPage.js (L82–95, L201, L360) Medium Hardcoded Model 2/3/5 Visuals & +-X cm ease Sign Bug Negative ease rendered +-1.5 cm ease; Return Risk gauge was hardcoded to 16%; Model 2 probability to 69%; Radar chart labels to 68cm / 78cm / 41cm. Fix: Connected all gauges and radar labels to live ML outputs and fixed sign formatting.

frontend/pages/HistoryProfilesPage.js (L40–48)		 Medium Onboarding Bounced Guests to Login & Vault Demo Cards Couldn't Be Selected Finishing onboarding sent guests to #/home (requiresAuth: true), bouncing them to #/auth. Fallback profiles on /history were not synced to store.state.profiles. Fix: Routed guests to #/measurements after onboarding and synced fallback profiles to the store.
